### 已知环境限制

本次执行环境对「写入大体积归档文件」有文件代理限制，`asar: true` 时 electron-builder 在写
`app.asar` 阶段报 `Brokered file token refused`。因此仓库配置为 `asar: false`（本地分发场景可接受），
其余打包链路（Electron 下载、原生依赖检查、签名跳过、DMG 生成）均已真实验证。

若在普通 Mac 上希望启用 asar，把 `electron-builder.yml` 的 `asar` 改为 `true` 即可。

## 4. 真实账号实机验证（2026-11-10）

在作者本人的账号上跑通，全程未读取浏览器 Cookie、未逆向签名。

| 步骤 | 观测 | 结论 |
| --- | --- | --- |
| 应用内扫码登录 | 资料接口返回 uid，`selfId` 识别成功 | 登录链路可用 |
| 页面传输启动 | `BRIDGE 就绪：user/self?showTab=message · 会话 45 · 消息 777` | 首屏 2s 内拿到数据 |
| 等待页面继续推送 | `会话 121 · 消息 1504 · 昵称 111` | 增量并入正常 |
| 一致性分析 | `messagesMatched 1504 / 1504` | 消息与会话 ID 完全对齐 |
| 落库检查 | `89 会话 / 777 消息`，`无主消息 0` | 存储归属正确 |
| 界面渲染 | 会话标题、成员数、气泡、时间线正常（见 `screenshots/chat-real.png`） | 可用 |
| 重启恢复 | 冷启动后自动恢复真实账号并继续同步 | 持久化可用 |

失败与修复记录（都靠日志定位，不靠猜）：

1. `Network.enable` 一直不返回 → 子窗口 `sandbox: true` 在 `--no-sandbox` 宿主下 DevTools target 不可用，改为 `false`；
2. 首屏 `get_response_body` 报 `No resource with given identifier` → 在 `about:blank` 上附加会跨进程换 agent，
   改为先把 douyin.com 真正加载完再附加；
3. `No data found for resource` → 在响应流还没结束时就读体，改为监听 `Network.loadingFinished` 再取；
4. 并发 `sendCommand` 报 `No resource` → 改为严格串行队列；
5. 消息区空白 → `bootstrap` 直接把列表第一项设为 activeId 却没加载消息，补了一个「activeId 变化即确保已加载」的副作用。
